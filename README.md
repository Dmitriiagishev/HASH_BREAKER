# ТОИБАС ДЗ
## Условие задачи
Восстановить пароли по известным криптографическим хэшам. Провосстанавливаемые пароли известны их длина и алфавит (уточняются преподавателем вмомент выбора этого ДЗ). Пароли не словарные. Время восстановления паролей к файлуиз 100 хэшей должно быть не больше 1 часа. Файл с хэшами для проверки выполнениязадания высылается после получения уведомления о готовности вас к приемке этапа 1.Это текстовый файл, где каждая строка – хэш пароля. Не позднее 1 часа должен бытьприслан файл с паролями, причём должно быть вскрыто не менее 50% паролей.

Длина пароля - 9 символов. 
Допустимые символы: 2468*WuiopZbvcs (15 различных символов).
Хэш-функция MD5(SHA1(SHA-256("someSalt2"+value+"Additional890"))).
## Brute-Force
Изначально планировалось решение при помощи brute-force перебора всех возможных вариантов пароля.
Все пространство паролей разбивалось на столько частей (чанков), сколько потоков поддерживает процессор компьютера, решающего задачу. Затем, по каждому из них начинался перебор всех возможных паролей из этого чанка с последующим сравнением их хэшей с содержимым входного файла.
Программа была реализована на языке python, но, в виду плачевной производительности, было принято решение перенести логику на язык c++.
К сожалению, даже при переходе на более производительныый язык, мощностей моего железа не хватало, и ноутбук с intel core i3, в среднем, находил ~14 паролей из 100 (тестовая выборка была случайно сгенерирована) при использовани 4 потоков для вычислений, а ноутбук с intel core i7 ~13 паролей из 100 на 8 потоках.
В теории, все пространство паролей можно разделить на 12 частей и 4 из них обрабатывать на одном ноутбуке, и 8 на другом, но, было обговорено, что, хоть задачу можно решить любым способом, подразумевалось решение с использованием радужных таблиц, так что, я не стал испывать этот метод (хотя, все еще хочу опробовать разделить вычисления на 2 машины).
## Rainbow table
### Rainbow_table_generator
Далее, для решения задачи было принято составить и использовать радужную таблицу. 
Т.к. всего возможно 15^9 (~38.4 млрд) вариантов паролей, необходимо, чтобы [длина_цепочки]*[количество_цепочек] >= 38.4 * 10^9, чтобы, в теории, вся таблица покрывала все возможные пароли (Хотя, на практике выяснилось, что итоговая таблица покрывает ~ 62% от всех возможных паролей с заданными условиями).
Для разумного компромисса между скоростью вычислений и занимаемой памятью, были выбраны num_chains = 38.450.000 (Среди этих цепочек нет слипшихся, но, потом их количество было дополнительно немного дополнено) и chain_length = 1000 (Хотя, как оказалось во время напичания кода для поиска, из-за особенностей реализации, 999).
Программа rainbow_table_generator.cpp, реализующая эту задачу, была написана на языке c++.
Итоговая таблица имеет размер около 1.5 Гб и считалась на протяжении 31 часа.
### Hash_breaker
Далее, для поиска хэш функций по готовой таблице, была написана программа hash_breaker.cpp. Она принимает на вход два фала: rainbow_table.txt (получаемый при работе rainbow_table_generator) и hashes.txt (в котором записаны хэш функции, по которым необходимо восстановить пароли). Далее, программа начинает искать хэш-функции в данной таблице и, при нахождении соответствия хэш-функция -> пароль, выводит в консоль строку в формате 

<найденый пароль>  <соответствующая ему хэш функция из данного файла>  <заново посчитанная хэш-функция для данного пароля>

Хэш-функция еще раз считается для пароля, т.к. из-за ограниченных возможнстей функции редукции, достаточно много разных хэшей переходят в одинаковый пароль при ее использовании, что может вызывать ложно-положителььные срабатывания.

В среднем, при использовании данной фукции, вся таблица просматривается за ~ 10 минут, находя около 62 паролей из тестовой выборки, размером в 100 паролей, что, хоть и менее точно, по сравнению с brute-force, но, имеет колоссальную разницу в сскорости вычисления.
